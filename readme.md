 \<h2\>📘 Project Overview\</h2\> \<p\> This repository contains my personal portfolio website, built as a full-stack web application rather than a simple static portfolio. \</p\> \<p\> The original version of my portfolio was built primarily with \<b\>HTML, CSS and JavaScript\</b\> and was hosted through GitHub Pages. Moving away from keeping everything locally and learning how an application communicates with an online PostgreSQL database was one of the areas I wanted to gain practical experience with. \</p\> \<p\> Another major focus of this version was \<b\>JavaScript\</b\>. I wanted to spend more time understanding how JavaScript can be used alongside Flask and server-rendered HTML to make a website more interactive, rather than relying entirely on the backend for everything. \</p\> \<p\> The result is a portfolio application where projects and skills can be stored in a database, displayed dynamically through Jinja templates, managed through an administrator interface and updated without having to manually rewrite the public-facing pages. \</p\> \<p\> The project is still a personal learning project and is something I expect to continue improving as I learn more about full-stack development, security, databases and application architecture. \</p\>

 \<h2\>🛡️ Security\</h2\> \<p\> Security became a much more important part of this project as I moved from a static website to an application containing authentication and database operations. \</p\> \<h3\>🔑 Password Hashing\</h3\> \<p\> Administrator passwords are not stored as plain text. \</p\> \<p\> The application uses \<b\>Argon2\</b\> for password hashing and verification. \</p\> \<p\> The login process retrieves the stored password hash and verifies the supplied password using Argon2 before allowing the user to continue. \</p\>
---

 \<h3\>👤 Session Authentication\</h3\> \<p\> Protected administrator routes use a \<code\>login\_required\</code\> decorator. \</p\> \<p\> The decorator checks the current Flask session for an authenticated username and then verifies that the corresponding user still exists in the database. \</p\> \<p\> If the session is invalid or the user cannot be found, access is denied and the visitor is redirected back to the public website. \</p\> \<p\> There is also a \<code\>logout\_required\</code\> decorator which prevents already authenticated users from accessing pages intended for logged-out users. \</p\>
---

 \<h3\>🛡️ CSRF Protection\</h3\> \<p\> The application uses \<b\>Flask-WTF\</b\> for CSRF protection. \</p\> \<p\> CSRF tokens are included with sensitive forms and actions. The frontend also passes CSRF token data to JavaScript where required for interactive requests. \</p\> \<p\> Invalid CSRF requests are handled by a dedicated 400 error page. \</p\>
---

 \<h3\>🚦 Rate Limiting\</h3\> \<p\> The project uses \<b\>Flask-Limiter\</b\> to restrict certain actions. \</p\> \<p\> For example, the project like endpoint is limited to: \</p\> \<pre\> 5 requests per day \</pre\> \<p\> This was added to reduce repeated automated requests against the endpoint and to give me practical experience with rate limiting. \</p\>

Start the Application\</h3\> \<pre\> flask run \</pre\> \<p\> The development server can then be accessed through the local address provided by Flask. \</p\>
